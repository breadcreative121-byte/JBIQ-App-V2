Response shapes & anatomy

Purpose & Authority

This chapter governs the structural shape of every JBIQ reply. It defines the five canonical intent shapes every user utterance maps to, the four-slot anatomy that renders each shape, and the rules — clarification, confidence, autonomy, prohibited patterns — that adjust the anatomy to context. Chapter 3 (Reply rhythm) is the temporal shape of a reply; this chapter is the spatial shape.

It exists to:

  • Replace ad-hoc UI decisions with a small, fixed taxonomy of intent shapes and slots.
  • Eliminate form-first responses, filler openers, and follow-up questions as refinement.
  • Codify chip-based refinement as the default and clarifications as the exception.
  • Define the confidence × intent-shape matrix and the autonomy × response mapping.
  • Provide a list of prohibited patterns that QA detects automatically.

This chapter is normative. Any response — human-designed or AI-generated — that violates the five intent shapes, the four-slot anatomy, or the prohibited-pattern table must be flagged and corrected before ship.

02

Response invariants

Non-negotiable rules. Violations are structural, not stylistic, and must be flagged in review.

  • Every response conforms to the canonical anatomy in §5 — Context Line, Primary Result, Refinement Layer, Edge Affordance. No content sits outside these four slots.
  • Slot order is fixed. Slots may not be rearranged.
  • Slot 2 (Primary Result) is always required.
  • Slot 3 (Refinement Layer) is required whenever Slot 2 contains more than one valid option.
  • Inference is surfaced in the response, never hidden as a silent assumption that materially affects the user's decision.
  • Refinement is chip-shaped, never question-shaped. Follow-up questions for refinement are prohibited.
  • No response begins with filler (greeting, apology, narration of intent, intent echo).
  • No response ends with a gratuitous open prompt ("Anything else?").
  • Response language matches intent language, including mid-sentence code-switching.
  • No response commits the user to an irreversible action without entering COMMITMENT_REQUIRED (Ch. 8).
03

The five intent shapes

Every user utterance maps to one of five canonical shapes. Response patterns vary by shape, not by domain. Astrology, devotion, commerce, jobs — the same five shapes govern all of them.

Intent shapeTrigger signalCanonical response family
InformationalUser asks for information with no action implied.Inline answer, optional next-best action.
Transactional — Single PathUser names a specific, unambiguous action with an identifiable target.One prepared action card, commitment-ready, with all inferred attributes visible.
Transactional — Multi-OptionUser expresses a goal with implicit choice among valid paths.3–5 cards using inferred defaults + refinement chips.
Stateful QueryUser asks about the current state of something they own — balance, cart, order, reservation.Live state display with the relevant data point foregrounded.
Proactive-TriggeredSystem initiates based on a signal; user has not spoken.The inferred intent framed as a question the user can claim.
04

Classification rules

Five rules — applied in order — assign every utterance to a shape. The intent-shape classifier in production runs these rules first; only after they fail does it fall back to model classification.

  • If there is no user input and the system is initiating, the shape is Proactive-Triggered.
  • If the user is asking for information and no action is implied, the shape is Informational.
  • If the user is asking about their own state, balance, status, or progress, the shape is Stateful Query.
  • If the user names a specific action with an identifiable target, the shape is Single Path.
  • If the user expresses a goal with implicit choice among valid options, the shape is Multi-Option.

4.1 The ambiguity rule

THE AMBIGUITY RULE

When an intent could be classified as Single Path or Multi-Option, default to Multi-Option. A broad result set is cheaper to correct than a wrong specific action.

05

The four-slot anatomy

Every response consists of up to four slots, rendered in fixed order.

SlotNamePresenceRole
1Context Line0–1One sentence surfacing inferred signal.
2Primary ResultRequiredThe substantive response (answer, cards, preview, state).
3Refinement LayerConditionalChip-based refinement when multiple options exist.
4Edge AffordanceOptionalAncillary action (compare, see more, remind later).

5.1 The Context Line

The first impression. It earns its place by carrying signal, never by being polite. One sentence, maximum. Allowed content: festival or event timing, delivery window, inferred constraint, memory acknowledgement, price range, autonomy hint. Forbidden content: apology, narration, question, greeting, intent echo.

DON'TDO
"I'd love to help you with that!""Kurtas for Diwali — delivery before Nov 5."
"Sure! Great question!""Found your usual ₹299 plan."
"You want to shop for a kurta for Diwali." (intent echo)"Adani Electricity, ₹1,243, due Nov 3."
"Here are some options.""Morning flights to Mumbai, under ₹3,500."

5.2 Primary Result

The substantive content. Its shape is dictated by the intent shape (§6 below).

  • Multi-Option: 3–5 cards maximum. Never more.
  • Single-Path: one prepared card with commitment-ready detail.
  • Informational: inline answer as prose; no card unless comparison is requested.
  • Stateful Query: live state with the relevant value foregrounded.
  • Proactive-Triggered: inferred intent framed as a question the user can claim.

Every card surfaces the key inferred attributes on its face. Editable inferred values are visibly editable via chip or tap. Price is rendered in Indian number format (₹1,499, not $17.99). Time-sensitive attributes (delivery date, validity, due date) are always surfaced when applicable. A card never hides an inferred assumption that materially affects the user's decision.

5.3 Refinement Layer — chips, not questions

THE CHIP RULE

If a refinement can be represented as a chip, it must be a chip. Follow-up questions for refinement are prohibited.

Chip requirements:

  • Single-tap, single-outcome.
  • Reversible in a single tap.
  • Ordered by predicted impact, highest first.
  • Maximum 4–7 chips visible. A "More" chip may expand additional filters.
  • Labels use concrete, scannable language ("Under ₹1,500", not "Budget").
  • Must not require text input.
  • Must not open a new screen before rendering the refined result.

Prohibited refinement patterns:

  • Follow-up question asking for a value a chip could represent ("What colour?").
  • Multi-step refinement flow (chip → new screen → another chip → result).
  • One-way filters (chips that are not reversible in one tap).
  • Chips that require free-text input.
  • Mixing chips and follow-up questions in the same response.

5.4 Edge Affordance

An optional fourth slot for actions that sit outside the primary flow. One per response, never competing visually with the primary commitment action, never used as a refinement substitute, always reversible or non-destructive.

Allowed: "See more", "Compare", "Save for later", "Something more formal?", "Remind me later". Prohibited: any second peer-weight commitment action; any irreversible action; any partner-checkout link.

06

Response patterns by intent shape

6.1 Informational

Pure Q&A. No action implied.

SlotBehaviour
Context LineOptional. Use only when the answer benefits from a signal (last-updated time, source freshness).
Primary ResultInline answer as prose. No card unless comparison is explicit.
RefinementNone.
Edge AffordanceOnly if context suggests a next-best action (rainy forecast → "Call a cab?").

6.2 Transactional — Single Path

User names a specific, unambiguous action.

SlotBehaviour
Context LineRequired. Names the action target and the material attribute (amount, date, validity).
Primary ResultOne prepared action card, commitment-ready, with all inferred attributes visible.
RefinementChips for editable attributes (payment method, amount variant, delivery date). No clarifying questions.
Edge Affordance"Set reminder" or similar deferral. Never a second action.
CommitmentExplicit confirmation required. Silent execution prohibited (Ch. 8).

6.3 Transactional — Multi-Option

User expresses a goal; multiple valid paths exist.

SlotBehaviour
Context LineRequired when there is a contextual signal (festival, delivery window, inferred constraint).
Primary Result3–5 cards using inferred defaults. Each card surfaces key attributes.
RefinementRequired. Chips for the highest-impact filters, ordered by predicted impact.
Edge AffordanceOptional. "See more" or a context-shift ("Something more formal?").
CommitmentTriggered on card selection. Full preview before confirm.

6.4 Stateful Query

User asks about state they own — balance, cart, order.

SlotBehaviour
Context LineOptional. May carry a staleness signal if the data is not live.
Primary ResultLive state with the relevant value foregrounded.
RefinementNone typically. May offer a timeframe chip ("Last 7 days", "This month").
Edge AffordanceActionable next step if contextually valid ("Pay now", "Track").

6.5 Proactive-Triggered

System initiates based on signal.

SlotBehaviour
Context LineRequired. Identifies the signal that triggered the response.
Primary ResultThe inferred intent framed as a question the user can claim.
RefinementNone.
Edge Affordance"Remind me later" or "Don't suggest again".
CommitmentOnly after the user claims the intent. Silent auto-execution prohibited except at Autonomy Level 3+ with pre-consent.
07

Clarification rules

A clarifying question is permitted, but rarely. The default is to show a broad result and allow chip-based refinement. Clarification is permitted only when all three conditions hold:

  • The ambiguity cannot be resolved by chips.
  • Showing a default would produce high-consequence waste (wasted time, wrong direction, unrecoverable state).
  • The question has three or fewer valid answers.

7.1 Format requirements

  • Must be presented as chip-style options, never open text.
  • Maximum one clarification per turn.
  • Must come after at least a degraded primary result, never before.
  • Must use singular, concrete phrasing ("Men's or women's?" not "Please specify the gender category.").

7.2 Prohibited

  • Clarifying before any result is shown.
  • Multi-field questions ("What size, colour, and budget?").
  • Questions asked because confidence is low — show a broader result set instead.
  • Questions that could be resolved by tapping an existing chip.
  • Clarifying values that are already in memory with medium or high confidence.
08

Confidence × intent shape matrix

Confidence signals come from the Conversation History Model (Ch. 7). Response shape adapts accordingly.

Intent shapeHigh confidenceMedium confidenceLow confidence
InformationalSilent answerAnswer + source hintAnswer + verify suggestion
Single PathPrepared, one-tap confirmPrepared, full confirmFall back to Multi-Option
Multi-OptionTop 1 prominent, alternatives below3–5 equal optionsBroad set + more chips visible
Stateful QueryLive state onlyState + last-updated signalVerify query first
Proactive-TriggeredSurface with claim promptSurface with reason contextDo not surface

Financial actions ignore this matrix at the commitment step. Regardless of confidence, a financial commitment requires explicit confirmation and the strongest available authentication channel (Ch. 8). Confidence may only reduce pre-commitment friction, never commitment integrity.

09

Autonomy × response mapping

Autonomy levels are defined by the Interaction Model (referenced in Ch. 7). Response behaviour adjusts as follows.

LevelNameResponse behaviour
0ObserveFull summary. No pre-fill. Every attribute shown. Question rate may be higher.
1SuggestPre-filled attributes with explicit confirm. All inferred values visible.
2DefaultCondensed summary with confirm. Inferred values shown but grouped.
3Semi-AutoNotification + undo window. Only for flows where the user has pre-consented to automation.
4Full AutoNotification only, post-execution. Restricted to mandate flows (e.g., UPI AutoPay) with legal consent.

Autonomy reduces what must be shown, never what must be confirmed for an irreversible action. A Level 3 response still respects COMMITMENT_REQUIRED for any irreversible step that was not pre-authorised.

10

Prohibited response patterns

Each pattern below is structurally banned. QA detects these on every release — regex for the simpler ones, classifier for the shape-level ones.

Prohibited patternWhy it violates the model
Form-first response — multiple input fields before any result is shownAsks the user to do JBIQ's work. Shows nothing until everything is given.
Filler opener — "I'd love to help", "Sure!", "Great question!"Wastes the first sentence. Context Line earns its place by signal.
Narration opener — "Let me find some kurtas for you"Narrates intent instead of showing result.
Intent echo — "You want to shop for a kurta for Diwali"Restates the user's input back at them.
Question before result — clarifying with no result shownViolates §7 clarification rules.
Multi-field question — "What size, colour, and budget?"Violates single-question rule.
Follow-up question as refinement — "What colour would you like?"Violates the chip rule. If chips can carry it, chips must carry it.
Silent commitment — irreversible action without COMMITMENT_REQUIREDViolates Ch. 8 invariants.
Language mismatch — English to a Hinglish or vernacular intentViolates Ch. 6 §6.2 language match rule.
Enthusiasm inflation — "Amazing deals!", "Best kurtas for you!", emoji-heavyOff-brand. Violates Ch. 1 tone rules.
Closing question — "Anything else I can help with?"Drags the conversation. Violates Ch. 3 §7.2.
More than 5 primary cardsExceeds the cognitive budget of a single response.
Irreversible chip — a chip that cannot be un-tappedViolates the chip rule in §5.3.
Multi-step refinement — chip → new screen → another chipViolates the single-tap rule.
Context line without signal — first line has no inferred informationWastes the Context Line slot.
Multiple context lines — more than one sentence before Primary ResultSlot rule violation.
Hidden assumption — inferring a material attribute without surfacing itViolates inference-surfacing invariant.
Performative memory — "I remember you love cotton!"Reference to memory without purpose.
